# Stream recommendation architecture

All automatic music selection uses MyWave.start as the final selector. MyWave.mix is the strict-quota adapter; offlineMix uses the same selector with an explicit scarcity policy. YourMusic retrieves and filters candidates; LocalRadio and remote radio pages are recall sources, not a second playback queue. MixMaker recipes define thematic candidate pools and a finite quota. PlaybackService places results into the one player queue; Smart Shuffle is placement, not ranking. Explicit selections and manual queue entries are never silently replaced by recommendations.

## Invariants
- Personal strict liked/discovery quotas use cumulative offsets; contextual and finite selections may fill missing slots from eligible candidates. Offline fallback may relax unavailable preferences, never exclusions.
- Track and artist entry points retain the seed. Continuation uses the original queue context, not unrelated global cached radios.
- One saved Stream style; legacy radio tune is migrated only in the absence of a saved style. Native playback toggles control placement/continuation, not a competing taste profile.
- Only accepted queued recommendations count as served; explicit seed playback is not a recommendation. Switching off continuation preserves manual queue entries.
- Mobile, TV and external controls share the playback service. Device transport does not select music.

Seasonal recipes remain anonymous and deterministic; singles/EPs retain release order. Blend builds a symmetric shared playlist from two exported taste codes, not a personal recommender; DJ sequences already-selected songs for audio transitions, not candidate recall. These contracts remain intact. Provider mix entry points on phone, TV and car browse now use providedStream. The system radio action delegates to PlayerConnection.playRadio, and spoken track requests use the contextual Stream queue rather than optional autoplay. Artist shuffle remains a finite collection. Live/episode provider entries bypass music selection. Other rare external paths and end-to-end behavior remain to be verified on devices. Real-device checks: seed relevance, sparse taste, offline/online transition, manual additions, rapid source switch, seek/pause during retune, playback on Station.

## Product-level UX contract
Ordinary search results, albums, playlists and library playback retain native order and controls. Personal and contextual Stream are both continuous recommendation sessions, never inherit shuffle/repeat, and do not expose an independent autoplay toggle. Selecting a new track context from the current song preserves manually queued successors; repeating the same request is idempotent. Live streams and episodes never start automatic music continuation. Guest sessions cannot start an independent Stream. Device output, sleep timer, audio settings and library operations remain independent of the recommendation context. Validate these rules on phone, landscape, TV and external media controls before release.

### Session continuity
The native queue file now persists source kind, seed, origin, manual additions and the continuation boundary, with optional fields for backward compatibility. Cold restore and system resumption reconstruct the same Stream context. Stream startup on touch and TV participates in the existing global PlayerConnection request token, so a later ordinary play request cancels an older pending Stream selection. Full media-controller concurrency, smart-shuffle restoration and cross-device session transfer remain separate verification tasks.

### Vibe naming and context preservation
English/Russian user-facing recommendation terminology is Vibe/Вайб; legacy resource identifiers, serialized origins and actual broadcast terminology stay compatible. Artist/collection starts retain a bounded representative sample of the original collection in the queue and saved session. Provider results are candidates; local relevance scores remain signals in the shared selector. Ordinary play and shuffle are unchanged. Remaining work: translations outside en/ru, all collection card and TV collection action surfaces, exhaustive depletion fallback, full build and device validation.

Vibe actions are available from collection cards and pages, TV collections and TV song actions. Collection page extras suppress duplicate card actions. Ordinary TV single-track taps no longer implicitly start a Vibe; explicit quick-pick behavior remains configurable. A genuine broadcast keeps its radio/live identity.

### Scarcity handling
The personal mixed-default Vibe may use a soft quota for a profile with no likes after strict selection fails; explicit 0/100 discovery and language endpoints are preserved. Contextual continuation tries scoped original recall, then one bounded recall from already-selected related tracks, then the oldest eligible past tracks if the catalog has supplied candidates (or the source is local/offline). No repeat fallback in Smart Shuffle or initial context selection; current/upcoming/manual tracks remain protected. Catalog paging and local scoring remain recall, not alternative final selectors. This restores part of original Prism's exhaustion behavior; multi-hour device validation is still necessary.

### Research-inspired ranking (2026-11)
Sources: Spotify Research, Modeling Users According to Their Slow and Fast-Moving Interests (https://research.atspotify.com/2022/2/modeling-users-according-to-their-slow-and-fast-moving-interests); Exploiting Sequential Music Preferences (https://research.atspotify.com/2023/10/exploiting-sequential-music-preferences-via-optimisation-based-sequencing); Yandex Sona technical report (https://arxiv.org/abs/2608.11015). These are independently implemented lightweight adaptations, not the proprietary models. A bounded, account-scoped short-term feedback signal decays over minutes and expires after idle gaps; durable feedback stays separate. Only meaningful actual listening or deliberate early skip updates feedback; an item can be classified once. Adjacent measured energy contributes a bounded weight even at neutral mood. Unknown acoustic measurements remain neutral. Neither signal changes hard filters, quota endpoints, manual queue entries, or audio transport. The pure learning tests run independently of Android SDK installation. Full Android tests and live evaluation remain necessary.

### Multi-objective calibration and candidate recall
Inspired by Spotify's Algorithmic Balancing of Familiarity, Similarity & Discovery (https://research.atspotify.com/publications/algorithmic-balancing-of-familiarity-similarity-discovery-in-music-recommendations), Mostra (https://research.atspotify.com/2022/04/mostra-balancing-multiple-objectives-for-music-recommendation), and work on recommendation-driven diversity (https://research.atspotify.com/publications/algorithmic-effects-on-the-diversity-of-consumption-on-spotify). Vibe now allocates title-language targets separately within discovery and familiar slots, preventing artificial correlation between independent sliders. Actual results still depend on eligible catalog availability; title script is not vocal language. Soft, decaying artist fatigue spans batches without preventing a narrow catalog from playing. Policy/queue/language endpoint filtering occurs before bounded candidate fusion, so rejected results do not crowd out valid tracks; remote page recall counts relevant candidates. These are original local heuristics, not the proprietary Spotify models. Added deterministic tests for the joint quota and cross-batch fatigue.

### Local co-listening graph
Research: Spotify MUSIG (https://research.atspotify.com/2021/10/multi-task-learning-of-graph-based-inductive-representations-of-music-content) and contextual sequential user embeddings (https://research.atspotify.com/2021/4/contextual-and-sequential-user-embeddings-for-music-recommendation). VibeGraph is a small, independent on-device approximation, not a graph neural network. Edges aggregate at most one weighted observation per session, normalize by the exposure of both nodes and shrink sparse evidence. Canonical recording keys combine duplicate uploads; artist edges generalize to unplayed recordings. Known genre conflicts retain the original LocalRadio safeguards; no new audio downloads or external service. Bounded to 20,000 positive history events, cached with the existing history snapshot, which is now account-keyed. Pure JVM graph tests cover session repetition, popularity bias, unseen tracks and skipped plays. Actual recommendation lift is not yet measured.

### Theme integration and personal recall isolation
Vibe is an embedded player surface, not an independent media theme. Its card uses native GlassSurface, current Material scheme, LocalUi shape, and shared controls with opt-in embedded foreground ink; fullscreen player behavior remains the default. Vibe's separate background toggle is removed from both phone and TV tuning (legacy stored fields are retained for migration compatibility). TV retains native dark theme policy and focus components. Personal recall uses positive, artist-balanced seeds and seed-scoped cached pages; unrelated contextual radios no longer leak into the personal candidate pool. A sparse profile uses eligible feed candidates as initial seeds. Inspired by Spotify's Generalized user representations (https://research.atspotify.com/2025/9/generalized-user-representations-for-large-scale-recommendations). UI screenshots and complete Android compilation still require device verification.
